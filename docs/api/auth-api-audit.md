# Авторизация CoGoal после переноса

CoGoal-auth, CoGoal-eureka и CoGoal-gateway перенесены из CoGoalOld в текущий backend CoGoalProject/CoGoal. Старый проект сохранён. Авторизация адаптирована под [контракт версии 1.2.0](openapi.yaml); main дополнен профилем на Hibernate и внутренней синхронизацией. Дата сверки — 14 октября 2026 года.

## Реализованные изменения

| Область | Текущее поведение |
| --- | --- |
| Вход | login принимает email либо username без учёта регистра, пробелы по краям удаляются. Поиск блокирует строку аккаунта. |
| Блокировка | Общий счётчик для обоих идентификаторов; 5 попыток, 30 минут, 423 ACCOUNT_LOCKED для заблокированного аккаунта. |
| Регистрация | Email, username, name, password. Username 3–32 символа из латинских букв, цифр и `_`; пароль минимум 8 символов, максимум 72 байта UTF-8. |
| Ошибки | JSON code/message/details, сообщения на русском, без отражения паролей и токенов. |
| Идентификаторы | users.id и auth_tokens.id — BIGINT IDENTITY; main использует ID пользователя из auth. В API ID — integer/int64, в JWT sub — десятичная строка. |
| Ответ с токенами | Обязательные accessToken, refreshToken, expiresIn, user. User соответствует AuthUser; профиль и баланс загружаются отдельно из main. |
| Logout | Требует access-токен, отзывает переданный refresh-токен. Refresh остаётся доступным без access-токена. |
| Пароль | Forgot/reset, одноразовые ссылки на 30 минут, 202 для неизвестного email, 410 для истёкшей/использованной ссылки; сброс снимает блокировку и отзывает refresh-токены. |
| Email | Запрос требует текущий пароль; адрес меняется после подтверждения. Новый email синхронизируется в main, refresh-токены отзываются. |
| Username | Изменяется в auth, проверяется уникальность, сразу используется при входе и затем доставляется в main. |
| Профиль | Auth outbox публикует UserRegistered/UserProfileUpdated в Kafka; main слушает события, сохраняет их через Hibernate и подтверждает после commit. Старые версии игнорируются, стартовые монеты начисляются один раз. |
| SMTP | Mailpit локально, внешний SMTP через настройки. Письма имеют очередь, повторы до срока ссылки и шифрование текста в базе. |
| Gateway | GET/PATCH users/me идут в main; PATCH auth/me/username и POST users/me/email-change — в auth. CORS разрешает Idempotency-Key. Внешний internal API закрыт. |

## Архитектура из проектной документации

[Архитектурная схема](https://github.com/CoGoal/project-documentation/blob/main/architecture/architectura-scheme.md) предусматривает отдельную БД на сервис, отсутствие прямого доступа к чужим таблицам и событие UserRegistered через Kafka. [Требование 2.3.3](https://github.com/CoGoal/project-documentation/blob/main/05-requirements.md) распространяет Kafka на асинхронные межсервисные события. HTTP-клиент auth → main заменён Kafka-издателем и слушателем; внутренний POST /internal/users удалён. Подтверждение публикации и обработка main — отдельные этапы. Ошибочные события хранятся в DLT для исправления и повторной доставки.

На GitHub API-документация пока указывает UUID; пользователь подтвердил, что актуальное решение — BIGINT и документация ещё не обновлена. Локальный контракт сохраняет согласованный BIGINT.

## Принятые решения по контракту

Единое поле login и переход на BIGINT согласованы с пользователем. AuthResponse.user описывает AuthUser вместо полного MyProfile: баланс и достижения принадлежат main, а не auth. PATCH users/me возвращает MyProfile и меняет только имя и аватар в main. PATCH auth/me/username возвращает AuthUser без имени и аватара. Auth больше не хранит эти поля в users; события аккаунта не перезаписывают их в main. Профиль main может быть ещё не создан сразу после регистрации и отвечать PROFILE_PENDING.

Приложенный SQL подключён через Liquibase formatted SQL; добавлен обязательный заголовок формата. users хранит одну роль USER/ADMIN, совместимый roles в ответе и JWT вычисляется из неё. Общая таблица auth_tokens хранит REFRESH, PASSWORD_RESET и EMAIL_CONFIRM; family_id сохраняет защиту от повторного использования refresh-токена. Старые миграции не изменены: новые changeset импортируют аккаунты и токены, повторно ставят профили в outbox. После проверки переноса миграции 010–011 удаляют legacy-таблицы auth. Main переносит баланс и createdAt по внутреннему legacyId. Старые access-токены с UUID после перехода требуют refresh или повторного входа.

Регистрация не переносит данные из старой базы. Новые сервисы используют текущую базу main и отдельную cg-auth. При дальнейшем импорте старых аккаунтов потребуется проверить username на соответствие новым ограничениям и синхронизировать профиль. Изменение JWT_SECRET также меняет ключ шифрования очереди писем; старые ожидающие письма нужно доставить до такой смены или запросить новые ссылки после неё.

## Проверки

Проверки изменённых модулей auth, main и gateway: 118 тестов, 0 ошибок, 0 провалов, 0 пропусков. Тесты удалённого HTTP-транспорта заменены проверками Kafka-публикации и слушателя. Добавлены проверки владения профилем в main, отдельной смены логина, запрета изменения username через main и поздней регистрации без перезаписи пользовательских изменений. Docker-образы пересобраны, compose запущен. Проверка через gateway и Mailpit прошла с Kafka-синхронизацией. Отдельная проверка брокера подтвердила: регистрация и публикация при остановленном main; сохранение outbox при остановленном Kafka и доставка после восстановления; повторные и старые события без повторного начисления монет; сохранение ошибочного сообщения в DLT и обработка следующего сообщения. PostgreSQL-тест миграции сохраняет аккаунты, токены и outbox и допускает повторный запуск Liquibase. Все шесть прежних локальных профилей сохранили имена, аватары, баланс и дату создания после переноса.

Тесты auth проверяют регистрацию, нормализацию, общий лимит попыток, JWT/refresh, одноразовые и просроченные ссылки, одновременный сброс по одной ссылке, подтверждение email, изменение username и очередь SMTP. Тесты gateway проверяют реальные маршруты, CORS, передачу Authorization и закрытие internal API. Проверка запущенного compose дополнительно проходит регистрацию, вход, профиль, повторную и старую доставку, реальные письма Mailpit, reset, email confirmation и logout через gateway.

## Оставшаяся работа вне переноса авторизации

Цели, пакты, платежи, отчёты, магазин и поддержка в текущем main ещё не реализованы. [Сопоставление маршрутов старого проекта](endpoint-comparison.md) сохраняет основу для их адаптации; совпадение адресов не означает совпадение DTO и бизнес-правил. Статистика и достижения минимального профиля пока пустые, так как этих доменов в текущем main нет.

Фронту нужны страницы сброса пароля и подтверждения email по ссылкам. При истечении access-токена перед закрытым logout его следует обновить через refresh. Ошибки недоступного SMTP оставляют письмо в очереди; после истечения 30 минут нужна новая ссылка. Стартовые монеты по умолчанию равны 100 и задаются настройкой INITIAL_COINS.

Разделение профиля: Liquibase удаляет name/avatar_url из текущей auth.users; временный payload регистрации в outbox очищается после подтверждения Kafka. Main принимает схемы событий 1 и 2, сохраняет профильные поля при любых изменениях аккаунта и корректно обрабатывает позднюю регистрацию.
